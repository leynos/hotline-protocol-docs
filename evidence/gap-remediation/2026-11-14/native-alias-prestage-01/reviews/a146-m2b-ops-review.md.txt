## Consequential pre-pin corrections

1. **Per-action identity is still weaker than B118 item 2.** In
   `ui-input-alias-live-02.py` lines 58–104, the gate checks the saved
   display command and active unit, disk receipt, current emulator UID/
   start/netns and FD6 inode. It does **not** compare the display service's
   actual MainPID/start/executable to a bound receipt; it compares only the
   *saved* emulator executable SHA, without hashing current `/proc/PID/exe`,
   and does not check current FD16 path/inode after capture phase. A process
   with matching PID/start/UID/netns/FD6 but a different executable or lost
   capture FD passes the UI gate. Likewise an active replacement display
   unit can pass if its saved command is unchanged. B118 explicitly requires
   the live process/display/FD chain at every action. Recheck those facts
   before X opens, using existing receipts/current `/proc`; record any
   display start identity in the reviewed pre-stage receipt if necessary.
2. **Retirement is not single-use after an uncertain click.** Lines
   199–214 choose Quit or Quit Now by counting only `status=completed`
   retirement log rows. A prior `status=attempted` row with no completion
   selects Quit again. Because the attempted row is fsynced before X opens
   and an exception can occur after the button event but before the
   completed row, a second invocation could send a duplicate Quit. The
   no-X sequence model confirmed `[] -> Quit`, `[attempted] -> Quit`,
   `[attempted,completed] -> Quit Now`. Treat any unresolved attempt as a
   stop requiring supervisor review, not as an unused click. Keep the
   existing narrow root-0600 approval, fresh image and 60-second gate.
