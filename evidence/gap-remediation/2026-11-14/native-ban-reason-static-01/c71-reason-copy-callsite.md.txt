## Request 110 option 2 caller

`native-account-identity-01/oracle-queries/ID-D-10015e70.c:22-53` is the
request 110 handler. It selects field 103 target, field 113 option 2, then
checks field 101 (`0x65`). If absent, it sets `local_160=0`. If present,
it calls `FUN_10056b60(param_4,0x65,auStack_15f,0x3f)` and stores the return
byte in `local_160`. The next call passes **`&local_160`** as fourth argument
to `FUN_10006230`, with same target address for both range endpoints.
The stack declaration places `auStack_15f[63]` immediately after the
one-byte `local_160`; this is consistent with a length-prefixed staging
buffer, but the exact field helper return/copied-byte contract is not in a
retained standalone `10056b60` source and is not proven by layout alone.

`B06-D-10006230.c:32-42` sets the record's reason length from the first byte
of that passed pointer, caps it at 63, and calls
`FUN_100539c0(record+0x32,param_4,reason_length)` with the **unadjusted
pointer**. `endpoint-oracle-02/raw/EP2-A-10006230.json` confirms at
`1000635c–10006368`: r3=`record+0x32`, r4=`r31` (saved fourth argument),
r5=`record[0x31]`, then branch to `100539c0`. Thus the constructor copies
`reason_length` bytes starting at the pointer's first byte. This is an exact
machine-argument finding. It does not establish what `10056b60` wrote after
that first byte, nor that the resulting bytes equal wire field 101 text.

## Options Save path

`B17-D-100023a0.c:110-233` loads the existing ban list via `1000a070`,
passes it into `1001ddb0`, then on Save uses `1001e170`, writes the list with
`10009d10`, and calls connected-client producer `10006590`. There is **no

transform is delegated to UI helpers including `1001e7a0`; the retained

construction. Therefore the request-110 pointer result must not be applied
to Options reasons without another caller trace.
