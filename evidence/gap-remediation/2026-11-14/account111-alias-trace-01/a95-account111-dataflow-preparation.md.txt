## Exact safe Code-byte mapping and negative filter

The [offline scan receipt](a95-account111-code-offset-scan.json) records the
PEF section header, input hash and every matching aligned word. PEF magic is
`Joy!peff`, section count 3. Section 0 has kind 0 (Code), default address 0,
file offset `0x25d0`, packed = unpacked = total size `0x88718` (558,872
bytes). The frozen `S005-segments.json` identifies the loaded initialized
Code span `10000000..10088717` of exactly that size. Thus **for this
uncompressed section only**, aligned section offset `i` maps to loaded
`10000000+i` and file offset `0x25d0+i`. The mapping is independently
checked at `10014df0`: frozen
`account-attribute-01/queries/AA-A-10014df0.json` reports the first four
PPC words `7c0802a6 bf41ffe8 90010008 9421f960`, which exactly match file
offset `0x173c0`. This does not map PackedData or another PEF section.

Scanning 139,718 aligned Code words, low16=`0254` occurs 12 times: nine
branches (`primary opcode 16/18`) and three zero/data words;
low16=`0256` occurs zero times. **No**
`addi/lwz/lbz/lhz/lha` word has either direct positive displacement. The
receipt retains exact words/loaded addresses/opcodes rather than declaring
them functions. This filter is a bounded negative only: a record on a stack
can make the slot's displacement negative, or pointer arithmetic/indexed
access can use another immediate. A whole-record copy needs no literal
field offset. The `0x254` branch immediate is not a field reference.

## Highest-value alias path

The positive trace starts at `100073c0`: it writes `0x2de` bytes to a
caller-supplied buffer and checks version 1. Frozen
`AA-C-100073c0.json` lists ten direct callers and exact call sites.
`100197e0` reads a record into stack `auStack_300`, uses its login/bitmap
fields to build a derived UI list, and passes that **derived entry** to
`10019e90`; it does not visibly forward the whole record. `10011960`
normal login and `10011ee0` delayed login pass a loaded record or derived
fields into authentication/settings helpers; existing decompilation shows
bitmap/name/password use, not a direct 111 read. `10007780` passes the whole
buffer to writer `1002c440`; that is the established preservation path.
These call sites are concrete and avoid guessing a nearby constructor.

Proposed future **at most eight content calls** on the owned saved
`independent-endpoint-01` server project, after renewed exact DATA/JAR
hash, PPC BE32 and 1,840-function identity gates, under nonblocking canonical
`oracle.lock`, `--no-analyze --discard` and before/after identity snapshots:

1. `disassemble_function(100197e0,offset=0,limit=500)` to map the record
